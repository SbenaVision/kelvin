# Kelvin v0.4 — Specification

**Status:** draft, in development on the `claude/compassionate-kare-20cec7` branch.

**Thesis.** Kelvin v0.4 estimates the empirical response geometry of any black-box pipeline mapping text-like input to a structured decision, by perturbing structurally discovered input units and measuring above-noise output movement, without labels, judges, or user-declared governing types.

---

## Goals (priority order)

1. **Drop the `governing_types` requirement.** When unset or empty, Kelvin perturbs every unit type that has ≥1 cross-case peer and emits a per-unit-type sensitivity profile. The profile *itself* reveals which unit types the pipeline treats as governing.
2. **Mechanical perturb-all-units mode.** With no `governing_types` declared, the full perturbation battery runs across all detected unit types without pre-classification. Pillar 2 (`swap_condition`) gracefully no-ops on units it can't parse.
3. **Explicit `signature.json` artifact.** One named, versioned artifact at `kelvin/signature.json` bundling every pillar output (raw scores, noise floor, decomposition, mechanical sensitivity, per-type profile) as a structured response-geometry vector. Downstream tools can index it.
4. **Backward compatibility.** v0.3.0 configs with `governing_types: [...]` declared continue to behave byte-for-byte identically — same `report.json` content, same per-case structure, same regression-harness output.

## Non-goals (deferred)

- **Auto-unitization across non-markdown formats** (plain text, JSON, HTML). The v0.3.0 markdown parser is kept as the only structural-discovery path in v0.4. Format unitizers ship in v0.4.x or v0.5.
- **Schema-inferred categorical typing.** Unit types continue to come from normalized markdown headers. Semantic / learned typing remains v2.
- **Maturity rubric.** v0.4 surfaces the geometry; v0.5 grades it.
- **EOS certification integration.** v1.0.

## Behavioral changes

### Configuration

| Field | v0.3.0 | v0.4 |
|---|---|---|
| `governing_types` | required, list[str] | **optional**; empty/unset = perturb-all-types mode |
| All other fields | unchanged | unchanged |

### CLI

No new flags. `kelvin check` behaves identically when `governing_types` is declared.

### Perturbation behavior

| Generator | Declared `governing_types: [x, y]` | Empty / unset |
|---|---|---|
| `reorder` | unchanged | unchanged |
| `pad_length` | unchanged | unchanged |
| `pad_content` | unchanged | unchanged |
| `swap` | fires only on x, y | fires on **every** unit type with ≥1 cross-case peer |
| `swap_condition` | parses x, y bodies | parses **every** unit type's body; non-rule-shaped types skip silently |
| Pillar 3 families | unchanged | unchanged |

In perturb-all-types mode, "case has no units of this type" warnings are suppressed (vacuous in all-types mode). "Peer pool empty" warnings are also suppressed when iterating auto-discovered types — singletons across the corpus are expected and not user errors.

### Output

#### Per-case `report.json`

Existing fields unchanged. The `sensitivity_by_type` map now contains **every type that produced swap samples**, not just declared governing types. In declared-types mode the map is unchanged.

#### Run-level `report.json`

Existing fields unchanged. New optional field `auto_governing_types: bool` set to `true` when the run was in perturb-all-types mode (omitted when `governing_types` was declared, preserving v0.3.0 byte-compat).

#### New artifact `kelvin/signature.json`

```json

  "schema_version": 1,
  "kelvin_version": "0.4.0",
  "seed": 0,
  "n_cases": 10,
  "decision_field": "stage_assessment",
  "auto_governing_types": true,
  "raw": {
    "invariance": 0.825,
    "invariance_sample": 280,
    "sensitivity": 0.571,
    "sensitivity_sample": 7,

  "noise_floor": {
    "eta": 0.0,

```

`signature.json` always emits, even on dry runs (with `dry_run: true` flag and null score values).

## Acceptance criteria

| ID | Test | Pass condition |
|---|---|---|
| AC-1 | v0.3.0 yaml with `governing_types: [gate_rule]` runs unchanged on the 6-VC-cases corpus | per-case `report.json` and run-level `report.json` are byte-identical to v0.3.0 except for additive `signature.json` |
| AC-2 | v0.4 yaml with no `governing_types` runs on the 10-case mixed corpus | exits 0; `auto_governing_types: true` in run-level report; `sensitivity_by_type` contains every type with ≥1 swap sample |
| AC-3 | Per-type profile from AC-2 contains `gate_rule` plus other types (e.g., `team`, `market_evidence`) | `sensitivity_profile.by_type` has > 1 entry |
| AC-4 | All existing pytest tests pass | `pytest tests/` returns 0 |
| AC-5 | `signature.json` schema validates against the documented shape | manual schema check |

## Implementation map

| File | Change |
|---|---|
| `src/kelvin/config.py` | Drop `governing_types` from `REQUIRED_KEYS`. `governing_types` defaults to `[]` when omitted. |
| `src/kelvin/perturbations/swap.py` | If `governing_types` is empty, build `types_to_swap` from `case.units` (sorted, unique). Suppress "peer pool empty" warnings in auto mode. |
| `src/kelvin/perturbations/swap_condition.py` | Same logic — iterate auto-discovered types when `governing_types` is empty; skip cleanly on non-rule-shaped units. |
| `src/kelvin/check.py` | `_echo_cost_preamble` accepts auto-mode and estimates swap targets per case. `_write_run_report` emits `auto_governing_types` flag and writes `signature.json`. |
| `src/kelvin/types.py` | No structural changes; reuses existing `RunScores`. |

## Out of scope (explicitly deferred)

- Plain-text unit detector (paragraph split)
- JSON unit detector (top-level keys)
- HTML unit detector
- Pyproject version bump to 0.4.0 (release-time concern)
- Maturity rubric (v0.5)
- EOS integration (v1.0)
- CHANGELOG.md update for v0.4 (release-time concern)
